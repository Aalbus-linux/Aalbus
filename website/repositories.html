Packages and hosting

Aalbus packages come from pkgsrc. Anyone can publish a repository, and anyone can mirror one.

How a repository works

A pkgsrc binary repository is a directory tree of package archives plus an index file. Nothing more is needed, so a repository can be served from any static web server or copied with rsync.

https://packages.example.org/aalbus/
    base-0.1.tgz
    ...
    All/
    pkg_summary.gz        index of every package

To use a repository, add its URL to pkgin:

# /usr/pkg/etc/pkgin/repositories.conf
https://packages.example.org/aalbus/

Where to host packages

Ideas for the project, roughly in order of how we would start:

OptionGood forTrade-offs
Object storage with a CDN (Cloudflare R2, Backblaze B2, S3) The primary repository. Cheap, fast, and easy to script from a build host. Needs an account and a small amount of money each month.
GitHub Releases Release-tagged artifacts and install images, visible to the community. 2 GB per file, not a CDN, and not a repository layout. Use as an archive.
Volunteer mirrors (rsync and HTTP, as NetBSD and FreeBSD do) Matches the decentralized goal best. Anyone can host a copy. Needs a published mirror list and a way to check mirrors are complete.
Your own VPS with nginx Full control. Good for a community-run primary. Ongoing maintenance and security updates.
Codeberg or Forgejo Fully open-source hosting for pages and releases. Smaller capacity than the large providers.
IPFS or torrents Extra redundancy for large images. Not a primary source. Availability depends on peers.

Trust and signing

Repository indexes and install images will be signed with a project key. Its fingerprint will be published here and in the repository, so you can check a mirror before you trust it.

Nothing is hosted yet. The first repository will be published after the base packages build cleanly.

Run a mirror

Once the first repository exists, mirrors will be listed on this page. The plan is to make every repository use the same layout, so any mirror is a complete copy.
